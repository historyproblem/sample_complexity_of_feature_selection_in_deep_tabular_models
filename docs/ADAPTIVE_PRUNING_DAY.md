# Дневной запуск: фиксированная база нормировки, адаптивная lambda

Ветка: `fix/resnet50-pruning-audit-20260905`. Команды из корня серверного
репозитория, без `nohup` и без обязательного `--output`:

```bash
.venv/bin/python scripts/launch_adaptive_pruning.py --config-name pruning_adaptive_day
```

Один новый `A1_internal_p18`, seed 42, с исходного нулевого initializer.
Ранее обученная модель не дообучается. Dense используется только как сохранённая
validation-кривая для контроллера и отдельный test baseline; заново не обучается.

- Внутренние каналы ResNet50, три бюджета до 18% текущих физических параметров.
- `20 search + 15 recovery + 20 search + 15 recovery + 20 search + 60 recovery`:
  ровно 150 тренировочных эпох, включая все восстановления.
- Цель при принятии всех сокращений — около 13 млн физических параметров.
  Фактическое число и принятие последней маски проверяются в `pilot_state.json`.
- Ориентир V100 по прежним логам: 2,5–3,5 часа, не гарантия. Wall limit — 4 часа
  с резервом для test. Реальный таймаут может оставить частичный результат;
  частичная модель не объявляется завершённой и не оценивается как итоговая.

## Что изменено

Дневной YAML явно задаёт `gate_regularization_normalization: initial_channels`.
В каждом гейтированном слое штраф равен сумме вероятностей открытых оставшихся
каналов, делённой на **исходную** ширину этого слоя, затем усредняется по слоям.
Удалённые каналы не дают градиента. Поэтому при неизменных вероятностях вырезание
других каналов не увеличивает коэффициент штрафа для оставшихся.

Lambda по-прежнему адаптивна, её состояние переносится между поисками.
Во время физического восстановления гейтов нет: штраф отсутствует, контроллер
сохранён до следующего поиска. В логе это `held_no_structural_gates`.

Также включён отдельный фикс контроллера: при слишком быстром закрытии каналов
сбрасывается накопленное ускорение шага lambda. Сравнение с прежним A1 оценивает
совместное изменение нормировки и этого исправления, а не чистую абляцию одного
фактора. Настройки optimizer, LR schedule, gate mode, recovery и защитные
проверки физического переноса не изменены. Устойчивость на реальных данных
не гарантируется одними синтетическими тестами.

Старые конфиги без нового поля сохраняют `enabled_channels`; старые checkpoint
читаются без изменения исходного смысла их регуляризации.

## Результаты

Логи выводятся в терминал и файлы. Новая папка:
`outputs/runs/<timestamp>_pruning_adaptive_day/`.

После завершения A1 немедленно оцениваются его замороженный deployment и ранее
сохранённый dense на всех 10 000 официальных test изображениях. Никакого обучения,
подбора checkpoint или обновления BatchNorm на test. Следующий job в любой
очереди не начинается, пока test завершённого job не сохранён.

- `test_evaluation/test_comparison.csv` и `.md`: итоговые test-метрики и физический размер.
- `test_evaluation/test_summary.json`: сводный статус, evaluated/pending jobs.
- `test_evaluation/A1_internal_p18/`: отдельный неизменяемый отчёт инференса,
  план checkpoint и предсказания; включает dense при первой оценке в очереди.
- `A1_internal_p18/pilot_state.json`: training status, точное число эпох,
  принятые маски, физические параметры, режим нормировки и исходные ширины гейтов.
- `A1_internal_p18/global_history.csv`: эпохи, validation, lambda, имя job,
  режим нормировки и число оставшихся каналов. Это не test-отчёт.

Тестовые результаты не меняют заранее заданную очередь или обучение.
Сравнения с DepGraph и предыдущими экспериментами остаются исследовательскими:
прежние test-результаты уже использовались при планировании новых опытов.

Проверить план без обучения и записи результатов:

```bash
.venv/bin/python scripts/launch_adaptive_pruning.py --config-name pruning_adaptive_day --cfg job
```
