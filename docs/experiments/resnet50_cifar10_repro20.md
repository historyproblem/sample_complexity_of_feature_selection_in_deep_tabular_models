# Проверка воспроизводимости: два одинаковых начала поиска

Команда последовательно запускает два новых Python-процесса с одинаковыми
данными, начальными весами, seed42 и порогами soft=.00025 / hard=.0005.
Каждый останавливается после 20 эпох. Всего выполняется 40 эпох обучения.

Это первые 20 эпох обычного поиска на 60 эпох: его `num_epochs=60`,
`CosineAnnealingLR(T_max=60)` и автоматический шаг lambda `.9210340371976183`
сохраняются. Первые 10 эпох lambda удерживается на `.001`, затем адаптируется.
Полный бюджет одной будущей модели остаётся 60+90=150 эпох.

Используется LS0, floor `.08`, L1 / tau `.5`, AdamW `.001` / weight decay `.0005`.
Рецепт сохраняет будущее окно выбора 31–60 и BN200 для физических кандидатов,
но этот диагностический запуск не доходит до выбора. Recovery, экспорт модели,
BN-калибровка кандидатов и official test не выполняются.

Все 20 checkpoint каждого повтора сохраняются для корректного продолжения
поиска и последующего выбора. Ориентир по диску — около 6 GB на повтор,
около 12 GB на пару; фактический размер зависит от содержимого checkpoint.
Предварительная проверка требует не менее 20 GiB свободного места.

Настройки CUDA/cuDNN/TF32 не меняются: фактические флаги записываются внутри
каждого дочернего процесса. Расхождение повторов является результатом проверки,
а не ошибкой запуска. Эта проверка сама по себе не устанавливает его причину.

## Входы

Нужен существующий `outputs/baseline/one_shot_dense_reference_seed42` с
`J1_dense_control/global_history.csv`, `pilot_state.json`, `resolved_config.yaml`
и `shared_random_seed42.pt`. Обученный dense checkpoint не нужен.

- SHA256 истории: `47b56d77615d01e9780f7765d10d144ad1f3d6db5897d777687661f4a6f23a76`.
- SHA256 zero-epoch initializer: `82e7232c8832ab6db93d4f551e6a5eb509a5a92089fc820620e05dd80b9b9422`.

При отсутствии входов или несовпадении хешей команда завершится до обучения.
Новый dense reference автоматически не создаётся.

Свежий `git clone` этих четырёх файлов не содержит. Для переноса подготовлен
отдельный `resnet50_repro20_inputs.tar.gz` с исходным initializer и именно
этими metadata. Архив передаётся отдельно от Git. Загрузите его в каталог
`outputs/` репозитория и распакуйте из корня репозитория:

```bash
tar -xzf outputs/resnet50_repro20_inputs.tar.gz
```

Внутри архива уже есть путь `outputs/baseline/one_shot_dense_reference_seed42/`.
До распаковки убедитесь, что этот reference-каталог отсутствует; существующий
reference можно передать напрямую через `--reference-output PATH`.
Для воспроизведения нужны прежние входы: новый reference после обучения с нуля
не заменяет их. Старый архив `one_shot_dense_reference_seed42.tar.gz` содержит
другую историю reference; его нельзя подставлять целиком вместо проверенного
пакета, даже если initializer совпадает.

## Запуск

Все команды выполняются из корня репозитория через его `.venv`.
При создании нового окружения устанавливайте зависимости через тот же Python:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Обычный `pip install` без активации `.venv` может установить зависимости
в общее окружение JupyterHub; `.venv/bin/python` их не увидит.

Локальная проверка рецепта без GPU, данных и существующего reference:

```bash
.venv/bin/python scripts/launch_resnet50_cifar10_repro20.py --validate-only
```

Первый диагностический запуск:

```bash
nohup .venv/bin/python -u scripts/launch_resnet50_cifar10_repro20.py > resnet50_cifar10_repro20_v1.log 2>&1 &
tail -f resnet50_cifar10_repro20_v1.log
```

Для проверки входов и GPU без обучения есть `--preflight-only`.
При другом расположении прежнего reference укажите `--reference-output PATH`.
Каталог результатов должен отсутствовать; существующие результаты никогда
не перезаписываются. Для отдельного нового повтора пары задайте новый `--output PATH`.

## Результаты

В `outputs/runs/resnet50_cifar10_repro20_v1` появятся:

- `repeat_1` и `repeat_2`: отдельные истории, состояния `search_paused`,
  все 20 checkpoint для последующего продолжения и `search_diagnostics`.
- `search_diagnostics/environment.json` внутри каждого повтора: версии,
  устройство и фактические настройки вычислений.
- `search_diagnostics/trace.jsonl`: хеши реально использованных batches,
  подробные события первых batches и состояния по завершении каждой эпохи.
- `comparison.csv`: значения метрик двух повторов по эпохам.
- `comparison.json` и `report.md`: первое зафиксированное отличие или совпадение.
- `study_state.json`: состояние выполнения обоих процессов.

Проверка не запускает следующие 40 эпох автоматически. Сохранённый checkpoint
позволяет отдельно продолжить поиск без повторной оплаты первых 20 эпох;
инструкция продолжения выдаётся после разбора диагностики.

Хеши и сохранение подробной диагностики добавляют накладные расходы. Точное
совпадение 20 эпох не доказывает совпадения всего 60-эпохового поиска или качества
будущего recovery. Official test этой командой не используется.
