# Четыре запуска с историческим отбором до BN

По решению пользователя от 26 октября 2026 воспроизводим две точки старой
чёрной серии `resnet50_cifar10_ls0_curve7_v2`, каждую с `min_keep_ratio=0.08`
и `0.001`. Это четыре независимых новых пути по 60 эпох search + 90 recovery,
всего 600 training epochs. Запускатель выполняет их последовательно.

| Порядок | Профиль | soft / hard | min_keep_ratio | Исторический ориентир |
| ---: | --- | --- | ---: | --- |
| 1 | `compact_5m_keep08` | 0.015 / 0.03 | 0.08 | 5.208M / test 93.07% |
| 2 | `large_15m_keep08` | 0.00025 / 0.0005 | 0.08 | 14.848M / test 93.72% |
| 3 | `compact_5m_keep001` | 0.015 / 0.03 | 0.001 | Вариант компактного рецепта с другим floor |
| 4 | `large_15m_keep001` | 0.00025 / 0.0005 | 0.001 | Вариант крупного рецепта с другим floor |

Пары soft/hard взяты из успешной чёрной серии с окном 31–60 и отбором до BN.
Для компактной точки используется именно `0.015/0.03`; `0.015/0.018` относится
к другому контрольному запуску, который дал 4.739M / test 92.58%.

## Правило отбора и BN

1. Рассматриваем только checkpoints эпох 31–60 включительно.
2. Оцениваем физически сохраняемые каналы на validation **до дополнительной
   BN-калибровки**. Допустимость: accuracy >= dense reference на эпохе 60 минус
   `hard_drop`. `soft_drop` управляет adaptive lambda, а не сортировкой кандидатов.
3. Среди допустимых выбираем минимум физических параметров. При одинаковом
   размере выигрывает выше validation, затем ниже CE, затем более ранняя эпоха.
4. Если допустимых нет, сохраняем исторический fallback: лучшая validation
   за 31–60, затем ниже CE и более ранняя эпоха. Старая компактная точка
   5.208M / 93.07% получена именно через fallback на эпохе 32; крупная —
   через допустимый checkpoint эпохи 42.
5. Импортируем выбранные surviving weights в физическую recovery-модель,
   выполняем BN200 только на train и начинаем 90 эпох recovery.

Дополнительная BN-калибровка выключена во всём search: у кандидатов и у
выбранного `search_*/export_only/deployment.pt`. За это отвечают одновременно
`one_shot.search_selection_bn_calibration_batches=0` и
`accuracy_guided.guard.train_bn_calibration_batches=0` в search-конфиге.
В recovery первый параметр остаётся нулевым, второй равен 200. Recovery
сохраняет решение search и не проводит повторного отбора search-checkpoint.
Обычные обновления BatchNorm внутри обучения остаются включены.

Предложенное ранее правило «лучшая accuracy в пределах +1% размера» не используется.
Сохраняются L1 по вероятностям открытия, исходная нормализация, adaptive lambda
с auto-step, entropy0, LS0 в обеих фазах, seed42, AdamW lr0.001/weight_decay0.0005,
нулевой weight decay гейтов и fresh cosine90 в recovery. В физической recovery
гейтов нет; состояние контроллера сохраняется в метаданных.

## Ожидаемые размеры и границы воспроизведения

5M и 15M в именах и `target_parameters` — ориентиры по исторической серии.
Они не входят в функцию отбора, не задают квоты ширины и не гарантируют размер.
Смена floor может менять выбранную архитектуру существенно: строгая пара с
floor0.001 раньше дала 4.660M / test93.31% (эпоха58). Компактная пара с floor0.001
раньше дала 17.300M, но выбрана была эпоха19, теперь исключённая из кандидатов.
Поэтому для вариантов floor0.001 нет подтверждённого прогноза около5M/15M.

Проверяем воспроизведение прежнего рецепта на текущем коде, а не побитовое
совпадение CUDA-траекторий. Исходные dense history и zero-epoch initializer
закреплены SHA256 в манифесте. Нового dense pretraining нет. Официальный test
используется только после фиксации validation-результатов всех четырёх моделей,
без обучения и BN-обновлений. Сравнение exploratory: прежние test уже известны.

## Проверка и запуск из корня репозитория

После переноса коммита на сервер используйте виртуальное окружение репозитория:

```bash
.venv/bin/python scripts/launch_resnet50_cifar10_ls0_prebn_repro4.py --validate-only
.venv/bin/python scripts/launch_resnet50_cifar10_ls0_prebn_repro4.py --preflight-only
```

Первая команда проверяет все восемь конфигов фаз и физические минимумы на CPU.
Вторая дополнительно проверяет реальные reference/initializer, CUDA и место
на диске. Она не запускает обучение. По умолчанию ожидаются прежние входы в
`outputs/baseline/one_shot_dense_reference_seed42`; иной путь передаётся через
`--reference-output`, без ослабления проверки хешей.

```bash
nohup .venv/bin/python -u scripts/launch_resnet50_cifar10_ls0_prebn_repro4.py \
  > resnet50_cifar10_ls0_prebn_repro4_v1.log 2>&1 &
tail -f resnet50_cifar10_ls0_prebn_repro4_v1.log
```

Результаты: `outputs/runs/resnet50_cifar10_ls0_prebn_repro4_v1/`.
В `final_results.csv` четыре строки с фактическими параметрами, floor,
soft/hard, validation и official test. `study_state.json` сохраняет выбранную
search-эпоху и правило отбора. При ошибке отдельного профиля остальные
продолжаются; команда завершается ненулевым кодом, если есть неудачные результаты.

Для повторного чтения законченных результатов используйте `--resume-completed`.
Проверяются прежний конфиг, floor, окно, отсутствие candidate/search-export BN,
хеши входов и бюджет. Частично обученный профиль автоматически не перезапускается.
По умолчанию вложенные checkpoints удаляются после проверки законченной фазы,
а выбранные root-checkpoints сохраняются; `--keep-nested-checkpoints` отключает
эту очистку и требует дополнительного места.
