# Адаптивный ночной прунинг, 9 сентября 2026

## Команда

Из корня серверного репозитория, в ветке `fix/resnet50-pruning-audit-20260905`:

```bash
.venv/bin/python scripts/launch_adaptive_pruning.py --config-name pruning_adaptive_nightly
```

Без `nohup` и без обязательного `--output`. Логи идут одновременно в терминал
и файлы. Результаты автоматически создаются в новой папке
`outputs/runs/<timestamp>_pruning_adaptive_nightly/`.

Проверить план без обучения, CUDA, загрузки данных и записи результатов:

```bash
.venv/bin/python scripts/launch_adaptive_pruning.py --config-name pruning_adaptive_nightly --cfg job
```

## Очередь и бюджет

| Конфиг | Метод | Бюджет удаления за цикл | Ориентир физических параметров |
|---|---|---:|---:|
| A1_internal_p18 | Обучаемый отбор внутренних каналов | 18% | 12,983 млн |
| A2_internal_p12 | Обучаемый отбор внутренних каналов | 12% | 16,047 млн |
| A3_internal_p23 | Обучаемый отбор внутренних каналов | 23% | 10,750 млн |
| A4_output_p05 | Обучаемый отбор выходных каналов | 5% | 20,189 млн |

Все четыре запуска используют **адаптивную λ**, один seed 42 и одинаковый
нулевой по обучению initializer. Каждая новая модель получает ровно **150 эпох**:
`20 search + 15 recovery + 20 search + 15 recovery + 20 search + 60 recovery`.
Если pruning transaction отклоняется, оставшийся бюджет уходит на восстановление
последней принятой структуры; дополнительные эпохи сверх 150 не выделяются.
Модели из прежнего 150-эпохового запуска не дообучаются.

Размеры — ориентиры `23 547 338 × (1 − budget)^3`, а не обещание достижения:
число каналов дискретно, сохраняются минимальные ширины и validation guard.
Для internal оставляется минимум 50% исходных каналов на каждой границе;
для output — минимум 25%. Это разные семейства физических архитектур.

План рассчитан примерно на 11–12 часов по прошлой V100, но новая адаптация
может повлиять на время. Общий safety cap в YAML — 12,5 часа, включая проверки
и финальный test. Перед новым запуском проверяется запас времени; при его
нехватке оставшиеся модели пропускаются, а завершённые всё равно оцениваются.
Для test резервируется 180 секунд. Дедлайн может прервать незавершённую модель;
это не будет выдано за её успешное завершение.

## Что именно адаптируется

Используется существующий `AdaptiveLambdaController`, а не фиксированный
коэффициент с новым названием. Стартовая λ = 0.001; warmup 10 глобальных эпох,
обновление каждые 3 эпохи по validation; окно accuracy — 3, допустимое падение
2/5 п.п. для мягкой/жёсткой границ. Сохраняются прежние параметры адаптивного
шага (по скорости закрытия ворот) и open-bias recovery контроллера. Есть
обратная связь `valid_average_zero_prob`; её отсутствие прерывает search.

Каждый search сохраняет полный контроллер в `best.pt` и `last.pt`.
Между циклами передаётся состояние **выбранного best checkpoint**, а не последней
эпохи: история accuracy, текущая λ, величина/усиление шага, состояние recovery.
Веса и BN/open-bias buffers в best относятся к реально измеренной validation;
после обновления контроллера дописывается только его metadata, не новые buffers.
Warmup и нумерация эпох не начинаются заново при переходе к следующему циклу.

Во время физического восстановления ворот уже нет: λ для модели равна 0,
а контроллер **удерживается**, не переинициализируется. При следующем gated
search его состояние восстанавливается. В логах это явно помечается
`held_no_structural_gates`, а не выдаётся за фиксированный pruning-пилот.

Адаптивная λ управляет силой штрафа при обучении ворот. Доля физически удаляемых
параметров — отдельный бюджет для построения кривой. Label smoothing, optimizer,
learning-rate schedule и функция ранжирования дополнительно не менялись.

## Существующий dense reference

По умолчанию используется завершённая дневная папка:

```text
outputs/runs/20260907_134446_507828_pruning_dense_control
```

Её validation-кривая — ориентир контроллера; её обученные веса **не** являются
инициализацией новых моделей. Из этой папки берётся исходный
`shared_random_seed42.pt` с `trained_epochs=0`. Проверяются хеши initializer
и deployment, конфиги, split, все 150 эпох validation и шаги оптимизатора.
Исходная папка остаётся неизменной. При переносе укажите `--dense-source PATH`.
Отсутствующий reference вызывает ошибку до обучения, а не скрытый baseline run.

## Итоговая метрика — test

После фиксации всех завершённых deployment автоматически запускается
`evaluate_pruning_test.py` на 10 000 официальных test изображений, включая
сохранённый dense reference. Обучение, выбор checkpoint и pruning guard
никогда не используют test. Итоговый файл:

```text
<run>/test_evaluation/test_comparison.csv
```

Также сохраняются `test_summary.json`, план выбранных checkpoint и предсказания
каждого test-примера. `comparison.md/json` в корне run остаются явно подписанными
промежуточными **validation**-отчётами; для итогового графика нужны `test_evaluation/`.
Главный конкурент — DepGraph. Старые его метрики требуют единого подсчёта
`correct_count / example_count`, прежде чем делать точные выводы о разнице.
Поскольку предыдущие test уже просмотрены, новая серия исследовательская,
а не подтверждение на полностью нетронутой выборке.

## Как убедиться, что λ работает

В каждом `<job>/global_history.csv` есть `lambda_used`, `lambda_next`,
`adaptive_lambda_action`, `adaptive_lambda_reason`, `valid_average_zero_prob`.
`adaptive_controller.json` и `pilot_state.json` фиксируют перенос выбранного
контроллера. В корректном контроллере λ может законно удерживаться или достигать
границы; это отличается от отсутствия контроллера. Synthetic preflight специально
задаёт обратную связь, при которой λ обязана изменяться, и проверяет оба цикла.

Исторический `pruning_nightly` и fixed-pilot оставлены для воспроизводимости;
они не являются новой командой выше. Не запускать старый конфиг вместо adaptive.

Локально прошли 239 профильных тестов: новая очередь, adaptive state handoff,
реальный двухцикловый ResNet50, старый fixed-pilot, физические Bottleneck,

два цикла internal и два output, по 10 синтетических эпох на модель; подтверждены
изменения λ, перенос выбранного состояния и физическое уменьшение моделей.

`--cfg job` и `git diff --check` также прошли. Полный GPU/CIFAR запуск локально
не выполнялся: серверная команда повторит preflight и synthetic GPU smoke.
