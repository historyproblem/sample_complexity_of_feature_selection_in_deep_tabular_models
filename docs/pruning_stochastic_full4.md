# Four fresh complete stochastic-ST models

This replaces the old search-only grid and five-model followup for the new server.
Use `scripts/run_stochastic_st_full4.py`; its default configuration is
`configs/experiment/pruning_v3/stochastic_st_full4.yaml`.

Exactly four models run sequentially. Every model finishes search60, inherited
physical recovery90, then frozen official CIFAR-10 test before the next search
starts. There are no scratch/random ablations, old search dependencies or waiting
for an old process. New training cost:4x150=600epochs; each deployment stays within150.

The first repeats the thresholds of the first stochastic-ST search from the old

Internal gates, Gumbel-hard ST training/noise1/temperature1, deterministic-hard

## Checkpoint disk usage

The older engine retained `epoch_NNNN.pt` for every epoch, including Adam state.
An actual saved full-search checkpoint is about283MB (270MiB), so60weights alone
are about17GB per search. Older recovery removed epoch files only after a branch
finished, leaving the full90-file peak while training. This can explain high disk
usage; it does not establish the cause of a particular server failure.

The new configuration enables bounded retention. After each completed epoch,
only the current validation-selection winner's numbered epoch file is retained;
RunHistory best/last snapshots and final selected/initial/deployment files remain.
During a save, a current candidate and atomic temporary files may coexist.
Unselected epoch weights generated by this new run are removed immediately.
Existing experiment folders are never cleaned or overwritten by this policy.

All30 search candidates are still scored with the original physical pre-BN
predictor and the same feasible/fallback ranking; metrics and masks remain in
`selection_candidates.jsonl` and the selection trace. Scoring happens online with
diagnostic RNG isolation. A constant reference and a maximum30-candidate window
allow keeping only the current winner's weights. Recovery uses the same best-
validation rule. CPU tests compare selected epochs, masks, weights and complete
training ledgers against archival retention for feasible and fallback cases.

Archival pause/resume/diagnostic APIs requiring every historical weight snapshot
are explicitly rejected with bounded retention. Completed fits are reused; partial
fits are retained and refused rather than silently restarting another150epochs.

## Reference input on a clean server

The same immutable dense reference and shared zero-epoch initializer are required.
Their content hashes are pinned. If the existing
`outputs/baseline/one_shot_dense_reference_seed42` is intact, it is reused.
Otherwise upload the already existing
`epoch_split_dense_reference_seed42_fresh_upload.tar.gz` to the repository root.
Only its four required reference/initializer files are imported, atomically, into
the new run's `reference_inputs` directory. A partial/corrupt old input is not
overwritten. There is no new dense baseline fit and no use of trained dense weights
as the search initializer. `--reference-archive PATH` accepts another archive path;
`--dense-source PATH` locates an intact existing reference. CIFAR-10 data downloads
automatically through the existing dataset loader if absent.

## Server command

The standard requirements file is used directly. No dependency bootstrap logic is
added to the Python launcher. `--no-cache-dir` avoids retaining downloaded wheels.
The foreground inspect step verifies inputs before a background job is launched.

```sh
if git fetch origin &&
   git switch feature/pruning-ablations-search-recovery &&
   git pull --ff-only &&
   (test -x .venv/bin/python || python3 -m venv .venv) &&
   .venv/bin/python -m pip install --no-cache-dir -r requirements.txt &&
   .venv/bin/python -c 'import torch; assert torch.cuda.is_available(), "CUDA unavailable"; print(torch.cuda.get_device_name(0))' &&
   .venv/bin/python scripts/run_stochastic_st_full4.py --stage inspect; then
  nohup .venv/bin/python -u scripts/run_stochastic_st_full4.py \
    > pruning_stochastic_full4.log 2>&1 < /dev/null &
  tail -f pruning_stochastic_full4.log
fi
```

Output:`outputs/runs/pruning_stochastic_full4_20261121`.
Each model uses `<id>/internal/search` and `<id>/internal/recovery/inherited`.
Test results accumulate in `test_evaluation/test_summary.json` and
`test_comparison.csv`, with frozen manifests and prediction hashes. The checkpoint
is selected only by validation; test has no training or BN updates and is isolated
from future training RNGs. Comparisons remain exploratory. To retry only missing
test inference after all four models complete,use `--stage test`.

Use `--dry-run` for a600epoch/no-training preview. On a retry after an incomplete
failed model, choose a fresh `--output` rather than overwriting a consumed budget.
