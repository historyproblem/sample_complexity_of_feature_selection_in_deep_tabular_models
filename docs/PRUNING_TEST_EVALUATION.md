# Оценка сохранённых deployment на CIFAR-10 test

В ночном запуске `20260907_200401_007709_pruning_nightly` измерялась validation,
а не test. Эта команда отдельно оценивает уже выбранные `deployment.pt` J1–J4
на всех 10 000 изображениях официального test. Обучения, подбора чекпойнтов,
изменения масок и перекалибровки BatchNorm нет.

Из корня репозитория на сервере, в ветке `fix/resnet50-pruning-audit-20260905`:

```bash
.venv/bin/python scripts/evaluate_pruning_test.py \
  --run-dir outputs/runs/20260907_200401_007709_pruning_nightly \
  --data data
```

Сначала проверяются **все** выбранные чекпойнты: статус завершения, хеши весов
и масок, сохранённая validation, строгая загрузка физической архитектуры,
число параметров/MAC, общий initializer, seed, split и бюджет обучения.
После этого начинается test inference в FP32, `eval()` и `inference_mode()`.
Веса и BN buffers проверяются на неизменность после оценки. Используется
исходная eval-нормализация CIFAR-10, без случайных аугментаций; последний
неполный batch учитывается. Прогресс виден непосредственно в терминале.

J1 автоматически ищется в исходной дневной папке из `reused_from`; при
переносе папок также проверяется соседний каталог с исходным именем. Если
он лежит в другом месте, добавьте `--dense-source PATH_TO_DENSE_RUN` (или путь
непосредственно к `J1_dense_control`). В одном только ночном архиве веса J1
отсутствуют: для сравнения с dense нужна и дневная папка.

Результаты сохраняются в `RUN_DIR/test_evaluation/`:

- `test_comparison.csv` и `.md`: test и validation в отдельных колонках,
  физические параметры, Conv/Linear MAC; accuracy в CSV — доля от 0 до 1.
- `evaluation_plan.json`: заранее зафиксированные чекпойнты и их хеши.
- `test_summary.json`: метрики, окружение, provenance и статус выполнения;
  финальный успешный статус — `completed`.
- `J*_predictions.npz`: индекс test-примера, label, prediction, probabilities
  и CE каждого изображения; позволяют позднее сравнить ошибки моделей попарно.

Файлы обучения и deployment не меняются. Уже существующий каталог результатов
не перезаписывается. При осознанном повторном запуске нужен новый `--output`;
не следует выбирать модель или чекпойнт по результатам test.

Дополнительные режимы:

- `--check-only`: только CPU-проверки чекпойнтов, без test, CUDA и записи файлов.
- `--jobs J3_internal_fixed`: оценка одной явно указанной модели.
- `--device cpu`: явное разрешение CPU inference, если нет CUDA.
- `--download`: разрешить загрузку CIFAR-10, если данных ещё нет локально.
- `--batch-size 128 --num-workers 2`: значения по умолчанию, можно изменить
  при нехватке памяти или ограничениях загрузчика.

Проверки реализации (не измерение качества на настоящем test):

```bash
.venv/bin/python -m pytest -q tests/test_pruning_test_evaluation.py
```

Локальная проверка 8 сентября: 30 новых тестов, вместе с серверным preflight
набором — 165 passed. `--check-only` прошёл на настоящих J2/J3/J4 из ночного
архива: совпали хеши, маски, физические параметры и MAC. Настоящих весов J1
локально нет; его путь проверен тестами повторного использования, а загрузка
dense-архитектуры — сохранением и восстановлением синтетического checkpoint.
Оценка на настоящем CIFAR-10 test и проверка CUDA здесь не выполнялись.
